Alembic is a database migration tool for SQLAlchemy.

Think of it like Prisma Migrate or Sequelize CLI migrations in Node.js.

Whenever you change your SQLAlchemy models, Alembic helps you apply those changes to your actual database without manually writing all the migration SQL.

## 1. Why do we need Alembic?

Suppose you have a SQLAlchemy model:

python

```python
class User(Base):
    __tablename__ = "users"

    id = mapped_column(Integer, primary_key=True)
    name = mapped_column(String(100))
```

Initially, your database table looks like this:

| id | name |
| --- | --- |
| 1 | Mohan |
| 2 | Sohan |

Now you add an email column:

python

```python
class User(Base):
    __tablename__ = "users"

    id = mapped_column(Integer, primary_key=True)
    name = mapped_column(String(100))
    email = mapped_column(String(150))
```

Question: How will the actual database know that you added an email column?

That's where Alembic comes in.

It detects the model changes and generates a migration.

## 2. How Alembic works

SQLAlchemy Models

Add email column

Alembic

Generate migration script

Migration file

ALTER TABLE users ADD COLUMN email...

Database

Schema updated

## 3. Install Alembic

bash

```bash
pip install alembic
```

## 4. Initialize Alembic

From your project root:

bash

```bash
alembic init alembic
```

It creates this structure:

text

```text
project/
│
├── alembic/
│   ├── versions/
│   ├── env.py
│   └── script.py.mako
│
├── alembic.ini
│
└── app/
    ├── main.py
    ├── database.py
    └── models/
        └── user.py
```

## 5. Configure database connection

Open `alembic.ini` and configure:

ini

```ini
sqlalchemy.url = postgresql+psycopg://postgres:password@localhost/mydb
```

For a real project, I recommend loading the URL from your application configuration instead of hardcoding credentials in this file.

## 6. Connect Alembic with SQLAlchemy models

Open `alembic/env.py`.

Import your SQLAlchemy Base:

python

```python
from app.database import Base
from app.models.user import User

target_metadata = Base.metadata
```

This tells Alembic where your database model definitions are.

Make sure all your models are imported so Alembic can discover them.

## 7. Generate migration

Whenever you change your SQLAlchemy models, execute:

bash

```bash
alembic revision --autogenerate -m "add email to users"
```

Alembic compares your SQLAlchemy metadata against the current database schema and generates a migration file.

Example generated migration:

python

```python
def upgrade():
    op.add_column(
        "users",
        sa.Column("email", sa.String(150), nullable=True)
    )


def downgrade():
    op.drop_column("users", "email")
```

- `upgrade()` applies the change.
- `downgrade()` reverses the change.

Important: Always review autogenerated migrations before applying them. Alembic cannot detect every schema change automatically.

You can also use as before for create empty migration file.
```
alembic revision -m "create users table"
```

## 8. Apply migration

bash

```bash
alembic upgrade head
```

Your actual database now has the new email column.

## 9. Rollback migration

Suppose you want to undo your last migration:

bash

```bash
alembic downgrade -1
```

To see migration history:

bash

```bash
alembic history
```

To see the currently applied migration:

bash

```bash
alembic current
```

## 10. SQLAlchemy vs Alembic

| Feature | SQLAlchemy | Alembic |
| --- | --- | --- |
| ORM | Yes | No |
| Database queries | Yes | No |
| Define database models | Yes | No |
| Schema migrations | No | Yes |
| Upgrade database schema | No | Yes |
| Rollback schema changes | No | Yes |

## 11. Node.js comparison

If you come from Node.js, this comparison should make it clear:

| Node.js | Python |
| --- | --- |
| Sequelize | SQLAlchemy |
| Sequelize CLI migrations | Alembic |
| Prisma ORM | SQLAlchemy ORM |
| Prisma Migrate | Alembic |
| TypeORM migrations | Alembic |

My recommendation: For your FastAPI + SQLAlchemy projects, always use Alembic for database schema migrations.

Official documentation: [Alembic documentation](<https://alembic.sqlalchemy.org/en/latest/?utm_source=chatgpt.com>).

One important distinction: Alembic is primarily for SQL databases used with SQLAlchemy. For MongoDB, you generally use a separate migration strategy.
